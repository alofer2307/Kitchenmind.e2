# Auditoría técnica — 4 de septiembre de 2026

## Estado inicial comprobado

`npm run build` terminó correctamente antes de modificar el producto. El proyecto tenía 16 rutas estáticas, PWA instalable y el árbol de trabajo sin archivos modificados; el último sprint local todavía no se había enviado al repositorio remoto.

## Funcionalidad existente y reutilizable

- Dashboard industrial calculado desde movimientos y eventos demo.
- Empleados, turnos, identificadores, asistencia y servicios.
- Scanner HID, reglas separadas e idempotencia.
- Cola offline en IndexedDB y sincronización automática del proveedor demo.
- Inventario, compras, calidad, actividad y Kiro en distinto grado de profundidad.
- Panel `/platform` con perfiles, planes, módulos, primera sucursal y administrador.
- Arquitectura `UI → hooks → services → repositories → providers`.
- Tipos multiempresa, auditoría operativa, feature flags y documentación viva.

## Deuda y riesgos encontrados

- La sesión administrativa y los datos operativos siguen teniendo `localStorage` como fuente demostrativa.
- El valor `platformAccess` del proveedor local se utilizaba para decidir el acceso a `/platform`; podía modificarse desde el navegador.
- El service worker guardaba una copia offline de `/platform`, evitando una nueva validación del servidor.
- No existía una base durable para usuarios, roles, MFA, sesiones o auditoría de plataforma.
- La selección visual de organización todavía no constituye aislamiento multi-tenant de producción.
- Los precios son presets demo; aún no existe catálogo versionado, cotizaciones ni contratos inmutables.
- Supabase Auth, PostgreSQL/RLS, invitaciones y pagos continúan pendientes.
- La sincronización offline todavía confirma contra el proveedor local, no contra un servidor autoritativo.

## Cambio mínimo elegido

El Sprint A no reescribe los módulos operativos. Convierte el despliegue a un Worker con D1 únicamente para proteger KitchenMind Platform y agrega:

- bootstrap de una sola propietaria mediante configuración privada;
- identidad autenticada verificada en servidor;
- roles y permisos separados de los clientes;
- segundo factor TOTP;
- códigos de recuperación de un solo uso;
- sesiones HTTP-only revocables;
- límite de intentos;
- auditoría durable;
- exclusión total de `/platform` y `/api/platform` del caché offline.

La persistencia comercial de prospectos, cotizaciones y organizaciones corresponde a los siguientes sprints. Hasta entonces, el configurador actual continúa siendo una demostración local explícita.
